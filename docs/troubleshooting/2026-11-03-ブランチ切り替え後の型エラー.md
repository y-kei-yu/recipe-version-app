# ブランチ切り替え後の型エラー

## 何が起きたか

mainブランチからチェックアウトしたchore/security-updateブランチで`npx next typegen && npx tsc --noEmit`を実行したらエラーが発生した

```
Generating route types...
✓ Types generated successfully
.next/dev/types/validator.ts:51:39 - error TS2307: Cannot find module '../../../src/app/recipes/page.js' or its corresponding type declarations.

51 const handler = {} as typeof import("../../../src/app/recipes/page.js")
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Found 1 error in .next/dev/types/validator.ts:51
```

## エラーの読み方

TS2307: Cannot find module '../../../src/app/recipes/page.js' or its corresponding type declarations.

- `Cannot find module 〜` は「〜というモジュール(読み込むファイル)が見つからない」という意味
- `Found 1 error in .next/dev/types/validator.ts` から、エラーが出たのは自分が書いたファイルではなく、next.jsが作成したファイルだと分かった

## 原因

- dev環境がmvp2で動かしたため、mvp2のブランチで作成したsrc/app/recipes/page.tsxがmainからチェックアウトした chore/security-updateブランチにはない
- .next フォルダは Git で管理していない ので、ブランチを切り替えても古いまま残った

## 解決法

- chore/security-updateでmake devを実行後、npx next typegen && npx tsc --noEmitをしたらエラーが出なくなった.
- 別の直し方：`rm -rf .next` で `.next` フォルダを消すと、次に起動したとき作り直される
- `npx next typegen` だけでは直らなかった理由：typegen が作るのは `.next/types/` で、エラーが出た `.next/dev/types/` は作り直さないから

## 学んだこと

- .next/dev/types/validator.ts は、開発サーバー（make dev → 中で next dev が動く）を起動したときに作られるファイル
- ブランチを切り替えたあとに、自分のコードと関係なさそうなエラーが出たら、まず.nextフォルダが古いか確認する。.nextフォルダを削除する
